# Privacy and Source Rules

## File Boundaries

- Treat raw documents as read-only source material.
- Put editable derivatives in a working-documents area.
- Put persistent learning records in the approved database area.
- Put generated reports in the approved output area.
- Never place API keys, tokens, personal answer banks, transcripts, databases, or private work documents in a public repository.

## Source Labels

Use one of these labels whenever personal material is structured:

- `Real experience`: confirmed as true by the learner.
- `Adapted experience`: based partly on real life but modified for practice.
- `Model answer`: an example used for language learning, not a personal claim.
- `Unverified`: status has not been confirmed.

Do not silently promote `Adapted experience`, `Model answer`, or `Unverified` content to `Real experience`.

## Question Labels

- Use `Official sample` only when the source is genuinely official.
- Use `Third-party recalled topic` for recalled question collections.
- Use `Practice question` for generated or unattributed questions.
- Preserve source notes when a question bank is imported.

## Output Safety

- Minimize personal detail in public examples.
- Do not expose local absolute paths in public reports or documentation.
- Confirm the destination before exporting a report.
- If saving fails, preserve the existing usable data and report the failure clearly.
